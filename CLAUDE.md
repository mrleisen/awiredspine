# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Single-page static site for the **A WIRED SPINE** music project, built with [Jaspr](https://docs.jaspr.site) (Dart) in static-render mode. Deployed to GitHub Pages at `awiredspine.com` via `.github/workflows/deploy.yml` on every push to `master`.

## Commands

```bash
dart pub global activate jaspr_cli   # one-time CLI install
dart pub get                         # deps
dart run jaspr serve                 # dev server with hot reload
dart run jaspr build                 # static output → build/jaspr/
dart analyze                         # lints (uses jaspr_lints)
dart format --line-length 120 .      # format (page_width 120, trailing_commas: preserve)
```

There is no test suite.

## Architecture

The Dart side is **structure only** — it emits HTML. All styling, interactivity, and data live in `web/`. This is the most important thing to internalize before editing.

### `lib/` — Jaspr (Dart)

- `lib/app.dart` — the entire page is one `StatelessComponent` (`App`) returning a `Component.fragment`. No state, no event handlers, no client-side logic in Dart.
- `lib/main.server.dart` — wires `<head>` (meta tags, OG/Twitter cards, Google Fonts link, `style.css`, deferred `hero.js` + `app.js`) and runs `App()` as the body.
- `lib/main.client.dart` — minimal hydration entrypoint; does nothing custom.
- `lib/main.{server,client}.options.dart` — generated by `jaspr_builder`, do not edit.

### `web/` — runtime

- `web/style.css` — **all** visual styling (~675 lines). No utility framework. Design tokens at the top: `--bg`, `--ink`, `--ink-dim`, `--acid` (#E3301A), `--line`.
- `web/hero.js` — full-screen `<canvas>` op-art (concentric rings + radial spokes + counter-rotating moiré). Black/white only; the acid red comes from CSS overlays on top.
- `web/app.js` — everything else interactive: the `RELEASES` data array + DOM build for `#rel-list`, the player iframe lazy-load on click (Spotify embed when a release has `spotifyEmbed`, else SoundCloud; `?play=<slug>` always uses SoundCloud to cue the track), UTC clock, hero parallax, the "virus" infection animation that flickers letters of `A WIRED SPINE`, the cursor crosshair, synthetic waveform polygons, and the nocturne typewriter loop.
- `web/assets/spine-logo.svg` — vector trace of `spine-logo.png` via `potrace`. **The SVG has no `fill` attribute** — consumers color it via CSS `filter: brightness(0) invert(1)` or `mask-image`. Don't add a fill.

### Where edits actually go

- **Add/change a release** → edit the `RELEASES` array in `web/app.js`. The `<ol id="rel-list">` in `lib/app.dart` is intentionally empty and populated client-side.
- **Change nocturne sentences** → edit the `data-lines` attribute on the `.nocturne` div in `lib/app.dart` (pipe-separated; `...` is a valid pause line).
- **Change visuals/animations** → `web/style.css` (most things) or `web/hero.js` (the canvas field).
- **Change page structure / SEO / `<head>`** → `lib/app.dart` for body, `lib/main.server.dart` for `<head>`/meta.

### Cache-busting

`style.css`, scripts, and SVG assets are referenced with `?v=N` query strings (e.g. `style.css?v=35`, `spine-logo.svg?v=5`). When you change one of these, **bump the version** in the references in `lib/main.server.dart` and `lib/app.dart` so deployed clients pick up the change.

## Lints (jaspr_lints)

`analysis_options.yaml` enables three diagnostics that will fail `dart analyze`:

- `prefer_html_components` — use `div(...)`, `span(...)`, `p(...)` etc. from `package:jaspr/dom.dart`, not `Component.element(tag: 'div', ...)`. Use `Component.element` only for tags Jaspr's helpers don't cover (e.g., `<canvas>`, raw `<meta property="og:...">` because the `meta()` helper doesn't accept `property`, inline `<svg>`/`<path>`).
- `sort_children_last` — the `children`/positional list argument must come last in the call.
- `styles_ordering` — keep CSS-style props in canonical order when used.

## Deploy

Push to `master` → GitHub Actions installs `jaspr_cli`, runs `jaspr build --verbose`, copies `CNAME` into `build/jaspr/`, uploads as a Pages artifact, and deploys. No server, no runtime deps in production.
